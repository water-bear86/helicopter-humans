# Offline log preparation

This is a tool for preparing a selected excerpt for sharing. It does not isolate an agent, hide its activity from its owner, protect runtime traffic or undo an earlier disclosure. The helicopter story and terminal are theatre. The hosted preview now accepts only invented sample text; it is not the place to paste real logs.

## Use

1. Download `offline-redactor.html` from the site, or build this repository with `npm run build` and use `dist/offline-redactor.html`.
2. Open the saved HTML file locally in a trusted JavaScript-capable browser. A served HTTP(S) copy refuses input. No server is required; code and styles are embedded.
3. Open a UTF-8 text file up to 2 MiB, or paste just the necessary excerpt. The original file is not modified. Oversized files are refused before reading; binary/non-UTF-8 text is refused.
4. Add private names, project names or sentences as exact phrases, one per line. Leading/trailing whitespace is trimmed; matching is case-sensitive and longer phrases take priority. Up to 200 phrases and 16,000 characters are supported. Common credential/identifier patterns are also masked.
5. Prepare the preview. Read all of it and edit any surviving private text. Confirm review, then save `reviewed-excerpt.txt` or explicitly copy the reviewed output. A change to the input/custom phrases discards the preview; editing the preview revokes review. Zero matches is not a claim of safety.
6. Clear the fields when finished. Clear also releases the export URL; leaving the page clears fields, including before back/forward cache. Existing files and clipboard contents are separate copies. Clear does not promise forensic memory erasure.

## Trust and privacy boundary

There are no network APIs, remote assets, analytics, storage APIs or automatic clipboard reads. The generated HTML embeds CSP hashes for its script and style, denies network connections and form submission, and loads no other resources. The CSP is a defense against accidental requests, not protection from malicious browser extensions, compromised browser/device software or modified downloaded code. Downloading the artifact still requires trusting the source of the code. Hosting sees the ordinary download request; the file-processing workflow is local.

The patterns are incomplete. Private prose, unknown credentials, encoded secrets, recovery phrases and identifying context can survive. Literal masking provides control over known terms; review remains essential. An excerpt that has already reached a third-party application cannot be made private retroactively.

## Validation

`src/redact.test.ts` covers short/quoted JSON credentials, escaped values, prefixed key names, auth/cookie headers, URL userinfo, Windows usernames, overlapping literal terms and unrecognised prose. `e2e/offline.spec.ts` exercises the actual emitted file at a `file:` URL on desktop and a mobile viewport: local file input, custom masking, reviewed text-only export, review invalidation, clear/reload, file refusal, zero workflow requests, CSP network refusal and the hosted input guard. It also checks the public terminal's echo/history boundary. These are Chromium checks, not proof of local-HTML support in every phone browser or file viewer.

The download is generated by `scripts/build-offline.mjs` from `src/offline.ts`, `src/redact.ts` and `offline/template.html` as part of the standard production build. No hand-edited second copy is maintained.
